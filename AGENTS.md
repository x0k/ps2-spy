# AGENTS.md

## Build & Run Commands

Task runner is [mk](https://github.com/x0k/mk) (invoked as `mk <target>`). Key targets from `mkfile`:

- `mk d` — run dev server (loads `.env.local` or `~/Sync/ps2-spy/.env`, uses `config/dev.yml`)
- `mk t` — run all tests (`go test ./...`)
- `mk l` — lint (`golangci-lint run ./...`)
- `mk f` — `go fix ./...`
- `mk b` — build binary to `bin/app`
- `mk text` — regenerate i18n catalog (`go generate ./internal/translations/translations.go`)
- `mk db` — regenerate sqlc DB code (`sqlc generate`)
- `mk dbl` — vet sqlc queries (`sqlc vet`)

Without mk: `go run cmd/ps2-spy/main.go --config <path>` or `CONFIG_PATH=<path>`.

## Verification Order

`go fix ./...` → `golangci-lint run ./...` → `go test ./...`

## Generated Code — Do Not Edit

- `internal/lib/db/` — sqlc-generated from `db/queries.sql` + `db/migrations/`. Regenerate with `sqlc generate`.
- `internal/translations/catalog.go` — generated by `gotext` from `//go:generate` in `translations.go`. Regenerate with `go generate ./internal/translations/translations.go`.

After editing `db/queries.sql` or `db/migrations/`, always run `sqlc generate`. After editing translatable strings in `internal/discord/messages/`, run `go generate ./internal/translations/translations.go`.

## Database Migrations

Migrations live in `db/migrations/` (sequential numbered `.up.sql`/`.down.sql` files). The app auto-migrates on startup via `internal/lib/migrator/`. To create a new migration:

```
migrate create -ext sql -dir db/migrations -seq <name>
```

To roll back one step: `migrate -source file://db/migrations -database sqlite3://storage/storage.db down 1`

Storage is SQLite (via `modernc.org/sqlite` — no CGO required). DB file location is set by `storage.path` in config.

## Config

Config loaded from YAML file (path via `--config` flag or `CONFIG_PATH` env). Falls back to env vars if file missing. Required fields: `discord.token`, `census.service_id`, `storage.path`, `storage.migrations_path`. See `internal/app/config.go` for all fields and env var names.

Dev config template: `config/dev.yml` (token and service_id must be provided externally).

## Architecture

Single Go binary (`cmd/ps2-spy/main.go`). Entry point wires everything in `internal/app/root.go` using a custom `module.Root` lifecycle manager (PreStart → Start → PostStop).

Key packages under `internal/`:
- `app/` — config, root wiring, logger
- `modules/events/` — Census WebSocket streaming per platform
- `modules/discord/` — Discord bot (slash commands, event handlers)
- `characters_tracker/`, `worlds_tracker/` — real-time PS2 state tracking
- `tracking/` — per-channel outfit/character tracking settings
- `stats_tracker/` — periodic stats collection with scheduled tasks
- `data_providers/` — adapters for population/alerts APIs (census, fisu, honu, ps2alerts, ps2live, saerro, sanctuary, voidwell)
- `lib/` — shared utilities (pubsub, loaders with caching/batching, census2 API client, diff, etc.)
- `storage/` — SQLite storage layer (wraps sqlc-generated `lib/db`)
- `discord/` — Discord message formatting, command definitions
- `ps2/` — domain types, repositories, outfit sync
- `translations/` — i18n (EN/RU) via `golang.org/x/text`

## Nix Dev Environment

`.envrc` uses `use flake`. The flake provides: Go 1.26, golangci-lint (unstable), sqlc, go-migrate, gotext, gotests, delve, air, and mk. Enter with `direnv allow` or `nix develop`.

## Docker

Production build uses `go build -tags "migrate"` (required for migrate source/file driver). Migrations copied alongside the binary with `STORAGE_MIGRATIONS_PATH=file://migrations`. Monitoring stack (Prometheus + Grafana) in `monitoring/docker-compose.yml`.

## Tools

- `tools/explorer/` — Census API query tool for debugging (outfit, character, world lookups)
- `tools/decoder/` — Census event decoder

## Transaction vs Begin

`Transaction` delegates to `Begin`, eliminating code duplication:

```go
func (s *Storage) Transaction(ctx context.Context, run func(s storage.Storage) error) error {
    return s.Begin(ctx, 10, func(tx *Storage) error {
        return run(tx)
    })
}
```

- **`Transaction(ctx, run func(Storage) error)`** — Defined on `storage.Storage` interface; callers receive only query access. Hardcoded buffer size of 10.
- **`Begin(ctx, expectedEventsCount int, run func(*Storage) error)`** — Method on `*sql_storage.Storage`; callback receives full Storage with all methods. Allows tuning buffer size.

The distinction is by design: external packages use the minimal `Storage` interface; internal code uses `*Storage` directly for full access.
